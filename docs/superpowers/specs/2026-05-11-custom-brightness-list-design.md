# 用户自定义亮度列表设计

## 目标

将当前硬编码的亮度命令列表改为用户可配置列表。用户通过 TrafficMonitor 插件设置界面输入空格分隔的亮度预设值，插件将其保存到配置文件，并用这些值生成右键命令菜单。

## 当前实现

当前亮度命令在 `src/Plugin.cpp` 中固定为 `0,10,...,100`。命令名称来自静态数组，点击亮度命令时通过 `command_index * 10` 得到亮度值。电源命令固定跟在 11 个亮度命令之后。

## 用户交互

插件重写 `ITMPlugin::ShowOptionsDialog(void* hParent)`，在 TrafficMonitor 调用插件选项时显示一个简单 Win32 设置窗口。

窗口包含：

- 说明文字：亮度值使用空格分隔，范围为 0 到 100。
- 单行输入框：显示当前配置文本，例如 `0 25 50 75 100`。
- 确定和取消按钮。

用户点击确定后，插件解析输入内容。解析成功时保存配置并刷新内存中的命令列表；解析失败时保存用户输入，但内存亮度列表为空，因此命令菜单只显示电源命令。取消不修改配置或内存状态。

## 配置文件

插件使用 TrafficMonitor 通过 `EI_CONFIG_DIR` 传入的目录保存配置文件。建议文件名为 `DDCCIPlugin.ini`，内容为：

```ini
BrightnessPresets=0 25 50 75 100
```

首次运行时，如果收到配置目录且配置文件不存在，插件自动创建配置文件并写入默认预设：

```text
0 25 50 75 100
```

在收到配置目录前，插件在内存中使用同一组默认预设，保证菜单可用。

## 解析规则

配置值必须是空格分隔的整数 token。

规则：

- 空配置视为无效。
- 任一 token 不是十进制整数时，整个亮度列表无效。
- 任一值小于 0 或大于 100 时，整个亮度列表无效。
- 合法配置按输入顺序生效。
- 重复值只保留第一次出现。

示例：

- `0 25 50 75 100` -> `0,25,50,75,100`
- `50 20 50` -> `50,20`
- `10 abc 50` -> 无亮度命令
- `10 120 50` -> 无亮度命令
- 空字符串 -> 无亮度命令

## 命令生成与执行

`Plugin` 维护动态亮度预设数组，例如 `m_brightnessPresets`，并用它替代固定亮度命令数量和 `command_index * 10` 计算方式。

命令顺序：

1. 当前有效亮度预设，命令名为 `亮度 N%`。
2. `电源 待机`。
3. `电源 关机`。

`GetCommandCount()` 返回有效亮度预设数量加 2。`GetCommandName()` 根据索引动态返回亮度命令名或电源命令名。`OnPluginCommand()` 对亮度命令使用 `m_brightnessPresets[command_index]` 设置亮度；电源命令索引根据当前亮度预设数量计算。

如果配置无效，亮度预设数量为 0，因此命令列表只包含两个电源命令。

## 错误处理

配置文件读取失败时，插件将亮度列表视为无效，只显示电源命令。

配置文件写入失败时，设置窗口返回 `OR_OPTION_UNCHANGED`，内存状态保持不变。插件不弹出额外错误提示，避免影响 TrafficMonitor 的菜单和刷新流程。

## 测试计划

新增或更新插件测试，覆盖：

- 缺少配置文件时初始化为 `0 25 50 75 100`。
- 合法配置生成对应亮度命令。
- 电源命令索引随亮度列表长度变化。
- 空配置、非法 token、超范围值会让亮度命令数为 0，只剩电源命令。
- 重复值按首次出现去重并保序。
- 亮度命令执行对应预设值，不再使用 `command_index * 10`。
- 设置窗口保存成功后刷新命令列表；取消不改变配置。
